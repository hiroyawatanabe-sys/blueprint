## 使い方

### 基本

各プロンプトは、**冒頭の `## ■ Prompt本文` 以下のコードブロックをコピー**して AI に貼り付ける。
`## ■ 設計意図` は運用者向けのメモであり、AI には渡さない。

### 添付するもの

すべての工程で **C1共通規律を必ず添付**する（または「C1に従うこと」と明記して同時に貼る）。
それに加えて、各プロンプトの `【INPUT】` に列挙されたものを添付する。

```
工程05 → C1 + C2 + C3 + 一括生成シート + 統合版コンテキスト
工程06 → C1 + C2 + 一括生成シート + 工程05出力 + 統合版コンテキスト
工程07 → C1 + C2 + 一括生成シート + 工程06出力 + 工程03出力(CTA設計)
工程08 → C1 + 工程06出力 + 統合版コンテキスト
工程11 → C1 + 工程08出力 + 工程06出力 + 工程02出力(競合分析) + 工程07出力 + 工程10出力
工程12 → C1 + 工程11出力 + 工程08出力 + 工程06・07出力 + 統合版コンテキスト
工程13 → C1 + 工程11出力 + 工程12出力 + 工程08出力 + 工程07出力
```

### 実行順

```
01 ヒアリング完璧化 ─ 02 USP創出 ─ 03 CTA設計 ─ 04 コンテキスト化
                                                      │
        ┌─────────────────────────────────────────────┘
        ▼
05 コンテンツ充填 ─ 06 ページ確定 ─ 07 導線差分 ─ 08 KW割当
                                                      │
        ┌─────────────────────────────────────────────┘
        ▼
09 REVOLUTION化 ─ 10 基本情報 ─ 11 title ─ 12 description ─ 13 h1
        ▼
14 見出し＋文章 ─ 15 CTA文言 ─ 16 一括入稿 ─ 17 フッター ─ 18 画像
```

工程05〜07は**シートへの差分**を出す。工程08・11〜13は**JSON＋レポート**を出す。
JSONは次工程にそのまま貼り付けて連鎖させる。

## 設計の背景（なぜこの形か）

### 2階層モデル

| 層 | 担当 | 決めるもの |
| :-- | :-- | :-- |
| 第0層 テンプレ設計 | 人間・業種ごとに1回 | 型A → 型A' の組み立て。ブロック順序・TOP型・CVページ数 |
| 第1層 案件充填 | 工程05〜13・案件ごと | 中身の充填。**順序・TOP型は再判定しない** |

過去案件（eはうす・ヨシハシ）で手動補正が17件発生した原因は、
**母集団が2系統に分かれていた**ことだった。
洗い出しは「35ページのWEBサイトの定義.xlsx」から選抜する一方、
実装は型Aシートの上で行われるため、型A外のコンテンツ・パーツが生まれていた。

型Aシートには「代用できるコンテンツ1〜3」「利用可能パーツ2〜4」という
**許容される自由度を定義した列が既に存在する**。
工程05はこの列を使って差し替えを行い、列外は起票する方式に変えた。

### 主要な確定ルール

| ルール | 内容 |
| :-- | :-- |
| 完全固定3ページ | `/privacy-policy/` `/sitemap/` `/compliance/` はページ名もスラッグも変更不可 |
| 事業形態で可変2ページ | `/company/` `/company/message/` は**スラッグ固定・表示名のみ**調整可 |
| 施工事例 | `/case/` に統一（`/projects/` `/voice/` を廃止） |
| CVページ | エコマド系＝`/contact/` 1枚／汎用型A＝CV独立4ページ |
| KW対象 | 固定3ページは対象外／可変2ページは指名系のみ |
| キーワード実査 | **行わない**。競合3社のFVキャッチとの埋没判定のみ（工程11に限界を明記） |
