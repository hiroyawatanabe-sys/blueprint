## 使い方

### 基本

各プロンプトは、**冒頭の `## ■ Prompt本文` 以下のコードブロックをコピー**して AI に貼り付ける。
`## ■ 設計意図` は運用者向けのメモであり、AI には渡さない。

### 添付するもの

すべての工程で **C1共通規律を必ず添付**する（または「C1に従うこと」と明記して同時に貼る）。
それに加えて、各プロンプトの `【INPUT】` に列挙されたものを添付する。

```
工程05 → C1 + C2 + C3 + 一括生成シート + 統合版コンテキスト(S14・S6-4・S8-1)
工程06 → C1 + C2 + 一括生成シート + 工程05出力 + 統合版コンテキスト(S7-4-3・S7-4-2)
工程07 → C1 + C2 + 一括生成シート + 工程06出力 + 工程03出力(CTA設計)
工程08 → C1 + 工程06出力 + 統合版コンテキスト(S4-2・S4商圏)
工程11 → C1 + 工程08出力 + 工程06出力 + 統合版コンテキスト(S5-3・S14・S6) + 工程07出力 + 工程10出力
工程12 → C1 + 工程11出力 + 工程08出力 + 工程06・07出力 + 統合版コンテキスト(S14)
工程13 → C1 + 工程11出力 + 工程12出力 + 工程08出力 + 工程07出力 + 統合版コンテキスト(S14)
工程14 → C1 + 【A】ページ別コンテキスト(S14・メタ確定値・CTA文言体系・確定台帳)
         + 【B】執筆指示書(工程09設置パーツのUUID列から自動生成) ※1ページ=1実行
```

**統合版コンテキストのうち、必ず含まれていることを確認する節**（改訂04で新設・拡張）

| 節 | 内容 | これが無いと止まる工程 |
| :-- | :-- | :-- |
| S4-2 | 種KWの構成要素分解／商圏 | 工程08（派生の起点と上限が無い） |
| S5-3 | 使用回避語リスト | 工程11（埋没判定が主観になる） |
| S7-4-3 | CTA着地先ページ要求リスト | 工程06（CV着地ページが欠落する） |
| **S14** | **事実・数値台帳** | **工程05・11・12・13・14（数字の出典が無い）** |

### 実行順

```
01 ヒアリング完璧化 ─ 02-1 競合分析 ─ 02-2 USP創出 ─ 03 CTA設計 ─ 04 コンテキスト化
（手動・Doc記入）      （回避語リスト）  （メイン確定）  （着地先リスト）  （S14台帳）
                                                      │
        ┌─────────────────────────────────────────────┘
        ▼
05 コンテンツ充填 ─ 06 ページ確定 ─ 07 導線差分 ─ 08 KW割当
                                                      │
        ┌─────────────────────────────────────────────┘
        ▼
09 REVOLUTION化 ─ 10 基本情報 ─ 11 title ─ 12 description ─ 13 h1
        ▼
14 見出し＋文章 ─ 15 CTA文言 ─ 16 一括入稿 ─ 17 フッター ─ 18 画像
```

工程05〜07は**シートへの差分**を出す。工程08・11〜13は**JSON＋レポート**を出す。
JSONは次工程にそのまま貼り付けて連鎖させる。

工程09でREVOLUTIONに設置したウィジェットの**UUID列から、入稿用パーツ構成JSONと
工程14用の執筆指示書が自動生成される**。工程14はこの指示書を「構造の正」として
1ページずつ執筆し、出力（PART A・入稿形式md）がそのまま工程16の入稿原稿になる。

## 設計の背景（なぜこの形か）

### 2階層モデル

| 層 | 担当 | 決めるもの |
| :-- | :-- | :-- |
| 第0層 テンプレ設計 | 人間・業種ごとに1回 | 型A → 型A' の組み立て。ブロック順序・TOP型・CVページ数 |
| 第1層 案件充填 | 工程05〜14・案件ごと | 中身の充填。**順序・TOP型は再判定しない** |

過去案件（eはうす・ヨシハシ）で手動補正が17件発生した原因は、
**母集団が2系統に分かれていた**ことだった。
洗い出しは「35ページのWEBサイトの定義.xlsx」から選抜する一方、
実装は型Aシートの上で行われるため、型A外のコンテンツ・パーツが生まれていた。

型Aシートには「代用できるコンテンツ1〜3」「利用可能パーツ2〜4」という
**許容される自由度を定義した列が既に存在する**。
工程05はこの列を使って差し替えを行い、列外は起票する方式に変えた。

### 主要な確定ルール

| ルール | 内容 |
| :-- | :-- |
| 完全固定3ページ | `/privacy-policy/` `/sitemap/` `/compliance/` はページ名もスラッグも変更不可 |
| 事業形態で可変2ページ | `/company/` `/company/message/` は**スラッグ固定・表示名のみ**調整可 |
| 施工事例 | `/case/` に統一（`/projects/` `/voice/` を廃止） |
| CVページ | エコマド系＝`/contact/` 1枚／汎用型A＝CV独立4ページ |
| KW対象 | 固定3ページは対象外／可変2ページは指名系のみ |
| キーワード実査 | **行わない**。競合3社のFVキャッチとの埋没判定のみ（工程11に限界を明記） |
| 数字の出典 | **S14 事実・数値台帳が唯一の出典**。台帳に無い数字をサイトに書かない。原文表記を改変しない |
| ページ構成の出典 | **型A（型A'）が唯一の出典**。参考サイト・既存サイトのページツリーを根拠にしない |
| CTA着地先 | 工程03がリスト化し、**工程06が充足する義務を負う**（未充足0件で発行） |

## 工程01〜04の改訂で解消した齟齬

改訂前、下流工程が要求する情報が上流に存在せず、担当者が手で補っていた箇所。

| 齟齬 | 原因（改訂前） | 解消（改訂後） |
| :-- | :-- | :-- |
| **①CV着地ページ欠落** | CTAを設計する工程03が、着地先ページを出力していなかった。工程06はCTAの存在すら知らない | 03に**CTA着地先ページ要求リスト**を新設 → 04 S7-4-3 に転記 → 06に充足確認STEPと「未充足0件」検査を追加 |
| 埋没判定が主観 | 工程11の検査6・7の材料が「FVキャッチの文字列」しかなかった | 02-1に**使用回避語リスト**（回避必須／要注意／空席）を新設 → 04 S5-3 → 11の検査が語の照合になる |
| 数字の出典が不定 | 工程11・12・13が揃って「実在する数字だけ使え」と規定しながら、実在の判定先が未定義 | 04に**S14 事実・数値台帳**を新設。C1「事実と証拠の規律」に判定先として明記 |
| USPの序列不明 | 3本を対等に出力。型AのMV枠は1つ、USP詳細タブは1USP＝1タブ | 02-2に**メイン／サポートの序列確定**を追加 → 05・06・07・11が判断せずに済む |
| 語彙の断絶 | 03はStage1-8、型AはB列の心理段階ラベル。工程07が毎回読み替えていた | 03に**Stage⇄型A心理段階 対応表**を内蔵。ページ種別も型A標準タブ種別に統一 |
| 旧工程の残骸 | 04 S8 が参考サイトのページツリーを「サイト構成」として転記していた | S8を**型A前提**に差し替え。参考サイトはデザイン参考に限定 |
| 種KWの派生範囲が不定 | 工程08が商圏を推測していた | 04 S4-2に**種KW分解と商圏**を新設。商圏外の地域語の派生を禁止 |
