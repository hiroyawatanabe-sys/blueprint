# 工程02-2｜USP創出（統合版 V3） 改訂パッチ v1.1

> **現行プロンプト（統合版 V3）は維持する。** 全面書き直しではない。
> 以下の【追記】を、指定位置に挿入するだけの差分パッチである。
> 大原則1〜6・STEP1〜6・出力フォーマットの骨格は一切変更しない。

---

## ■ 改訂の理由

現行プロンプトは「USPを3本、対等に並べて出す」設計である。
これは単体では正しいが、後工程が**3本を対等には扱えない**。

| 後工程 | 3本のUSPをどう使うか | 現行出力で足りるか |
| :-- | :-- | :-- |
| 工程05 コンテンツ充填 | 型A の「USP詳細1〜n」タブに**1USP＝1タブ**で充填 | 序列不明のため、どれがどのタブか決まらない |
| 工程06 ページ確定 STEP3 | 「確定USPの数（**メイン1＋サポート__**）」を入力条件に要求 | メイン／サポートの区別が出力に無い |
| 工程07 導線差分 | FVに置くキャッチは**1つ**（型AのMVブロックは1枠） | 3本のうちどれをFVに置くか決まらない |
| 工程11 title（TOP） | 「USPのメインキャッチ（S6 copy_set）」を素材にする | **「メインキャッチ」が定義されていない** |
| 工程12 description | 「数字・実績は統合版コンテキストに実在するものだけを使う」 | 根拠がサブコピーの文中に溶けており、抽出できない |

つまり現行は、**3本を1本に絞る判断を、下流の各工程に丸投げしている**。
過去案件で手動補正が発生した箇所の一部は、ここが原因である。

改訂は4件。**思考プロセス（STEP1〜5）は変更しない。STEP6の確定作業と出力項目にだけ追加する。**

---

## ■ 追記1｜STEP6に「メイン／サポートの序列確定」を追加

**挿入位置：** 「### STEP 6：キャッチコピーへの昇華（USPを3つ確定）」の箇条書き末尾

```
- **3本に序列を付ける（必須）。** 「メイン1本 ＋ サポート2本」を必ず確定する。
  - **メイン**：サイトのファーストビュー（MV）に置く1本。TOPページのtitle・h1の素材にもなる。
    選定基準は次の優先順とする。
      ① 空席（STEP4）に最も正面から立っているか
      ② 顧客が本当に欲しい状態（STEP2）の第1位に応えているか
      ③ 根拠事実が最も強いか（数字・年数・固有名詞を持つか）
  - **サポート1／サポート2**：メインを補強する順に並べる。
    型Aの「USP詳細」タブに、この順で1本ずつ充填される。
  - **【ストーリー型】を選んだ場合も序列は必要である。** 流れの起点になる1本がメインである。
  - 序列の理由を1行で添える。
```

## ■ 追記2｜STEP6に「根拠事実の分離」を追加

**挿入位置：** 追記1の直後（同じ箇条書き内）

```
- **各USPについて「根拠事実」をサブコピーから分離して書き出す（必須）。**
  サブコピーは"読ませる文"であり、後工程はそこから数字を抽出できない。
  そのため、次の形式で事実だけを独立させる。

  | 項目 | 記載ルール |
  |---|---|
  | 事実の原文表記 | コンテキストに書かれているとおりの表記（例：「創業50年」「施工実績2,300件」「江戸川区・葛飾区・墨田区」） |
  | 出典 | コンテキスト内のどこに書かれているか（例：①ヒアリング結果 > 2. HPの目的 > 強み） |
  | 種別 | 数字／年数／実績件数／資格・登録／地域／体制／保証 のいずれか |
  | 公開可否 | 顧客がサイト掲載を許諾しているか（不明なら「要確認」） |

  - **コンテキストに存在しない数字を、ここに書くことを禁止する。**
  - 根拠事実を持たないUSPがあってもよい（思想・体験で立つUSPは存在する）。
    その場合「根拠事実：なし（訴求の型：思想／人）」と明記する。
    ただし**メインは根拠事実を1つ以上持つことを推奨**する（title・descriptionが数字を使えなくなるため）。
  - ここで書き出した事実は、工程04で **S14 事実・数値台帳** に集約され、
    工程11・12・13・14 が引用してよい数字の唯一の出典になる。
```

## ■ 追記3｜STEP6に「使用回避語リストによる検査」を追加

**挿入位置：** 追記2の直後（同じ箇条書き内）

```
- **キャッチコピーを、工程02-1の「使用回避語リスト」と照合する（必須）。**
  現行の最終チェック「競合3社も同じことを言えるか？」を、語レベルで機械化する。

  【検査A】メインコピー・サブコピーに【回避必須】の語が含まれていないか
        → 含まれる場合は不合格。言い換えるか、絞り込んで別の約束にする
  【検査B】【要注意】の語を使っている場合、約束している便益が競合と異なるか
        → 同じ約束なら不合格。理由を1行で説明できない場合も不合格
  【検査C】各USPが使っている「武器の種類」を宣言する
        → 数字／実績／年数／地域／専門特化／保証・覚悟／人・ストーリー から1つ
        → 3本が同じ武器に偏っていないかを確認する（偏る場合は理由を記す）

  ※ 使用回避語リストが入力コンテキストに含まれていない場合、
    STEP1の停止条件と同様に作業を停止し、工程02-1の再実行を求める。
```

## ■ 追記4｜出力フォーマットへの追加

**挿入位置：** 「## 3. 出力フォーマット」内のコードブロック

### (a) 「■ USPの構成タイプ」ブロックの直後に追加

```
■ USPの序列
- メイン：USP__（理由を1行）
- サポート1：USP__
- サポート2：USP__
※メインをFV（MV）に置く。サポートはこの順で型AのUSP詳細タブに充填される。
```

### (b) 【USP 1】〜【USP 3】の各ブロック内、「▸ 競合も言えるか？」の直後に追加

```
▸ 区分：メイン／サポート1／サポート2（いずれか）
▸ 武器の種類：（数字／実績／年数／地域／専門特化／保証・覚悟／人・ストーリー から1つ）
▸ 根拠事実：
   ・原文表記：「______」／出典：______／種別：______／公開可否：______
   ・（複数ある場合は行を追加。無い場合は「なし（訴求の型：思想／人）」と記載）
▸ 回避語検査：【回避必須】語の使用 なし ／【要注意】語の使用 ______（使用時は約束の違いを1行）
```

### (c) 「■ 一言まとめ」の直後、コードブロック末尾に追加

```
■ 後工程への引き渡し
- FVキャッチ（MVに置く1文）：「（メインのメインコピー）」
- TOPページのtitle・h1の素材：上記メインキャッチ
  ※ ただし**そのまま転記してはならない**。title・h1は主役KWを含む形に作り直す
    （キャッチは情緒で成立してよいが、title・h1はKW条件を満たす必要があるため）
- 型A「USP詳細」タブに必要な数：__タブ（＝確定USP数）
- 工程06への申し送り：USP詳細タブを__本に増減すること
```

## ■ 追記5｜禁止事項への追加（既存5項目の末尾に3項目を追加）

**挿入位置：** 「## 4. 禁止事項（必ず守る）」の末尾

```
6. **3本のUSPを序列なしで出さない**。メイン1本を必ず指定する。序列を下流工程の判断に委ねることを禁止する。
7. **根拠事実の欄に、コンテキストに存在しない数字・年数・件数を書かない**。存在しない場合は「なし」と書くことが正しく、埋めることは誤りである。
8. **工程02-1の使用回避語リストが未添付の状態で、キャッチを確定しない**（検査A〜Cが実行できないため）。この場合は停止して差し戻す。
```

## ■ 設計意図（運用者向けメモ）

| 設計要素 | 狙い |
| :-- | :-- |
| メイン／サポートの序列を必須化 | 型AのMV枠は1つ・USP詳細タブは1USP=1タブ。3本対等では物理的に置けない。判断を上流に戻す |
| 根拠事実をサブコピーから分離 | 工程11・12が「実在する数字だけ使え」と言っても、抽出できる形になっていなければ守れない。S14台帳の材料を作る |
| 根拠事実「なし」を許容 | 思想・人で立つUSPを殺さない。ただしメインに推奨条件を置き、下流が数字を使えなくなる事態を予防する |
| 回避語検査を語レベルで機械化 | 現行の「競合3社も同じことを言えるか？」は良い問いだが主観判定。工程02-1の分解と接続して照合作業に落とす |
| キャッチのtitle転用を明示的に禁止 | キャッチは25字以内・情緒可、titleは27〜32字・KW必須。同じ文で両立しない。ここで釘を刺さないと工程11でキャッチのコピペが起きる |
