# 工程08｜KW割当 実行Prompt v1.0

> **新規工程**。G-Blueprint50形式（PART A JSON ＋ PART B レポート）。
> 上位検索KW①〜③から派生語を展開し、対象ページへ主役KW・サブKWを割り当てる。
> 添付：C1共通規律／工程06出力（確定ページ台帳）／統合版コンテキスト

### STEP 1｜対象ページの確定

工程06の確定ページ台帳を、3区分に仕分ける。

| 区分 | 対象 | 割当方針 |
| 対象外 | /privacy-policy/ /sitemap/ /compliance/ | KWを割り当てない |
| 指名系のみ | /company/ /company/message/ | 社名・屋号系KWのみ |
| 通常割当 | 上記以外の全ページ | 主役KW1語＋サブKW |

各区分のページ数を数え、以降の割当対象数を確定する。

### STEP 2｜種KWの分解と派生語の展開

上位検索KW①〜③を構成要素に分解する。
例：「内窓 江戸川区 補助金」→ ［サービス語：内窓］［地域語：江戸川区］［条件語：補助金］

分解した要素から、派生語を展開する。展開の軸：

a. **サービス語の派生**：内窓／二重窓／インナーサッシ／窓断熱／断熱リフォーム …
   （※統合版コンテキストの事業内容・USPに実在する範囲で展開する）
b. **地域語の派生**：市区名／隣接エリア／駅名／旧地名
   （※商圏として妥当な範囲に限る。実際に対応していない地域を展開しない）
c. **条件語の派生**：補助金／費用／相場／比較／選び方／事例／効果
d. **課題語の派生**：寒い／結露／カビ／騒音／ヒートショック／暑い
   （※工程05の充填内容・USPに実在する課題のみ）
e. **指名語**：社名／屋号／社名＋評判

**展開の制約**：コンテキストに実在しないサービス・地域・課題を派生語にしない。

### STEP 3｜ページ意図とのマッチング

各ページについて、そのページが答える検索意図を1文で書く。
（工程05の充填内容・工程06の表示名から導く）

例：/service/window/ →「内窓の設置を検討していて、内容と費用感を知りたい」

その意図に最も合致する派生語を、主役KWの候補として当てる。

### STEP 4｜主役KWの確定（1語＝1ページ）

通常割当ページに、主役KWを1語ずつ確定する。

選定基準（優先順）：
1. ページ意図を最も代表しているか（顔として張れるか）
2. 他ページの主役KWと重複していないか（**重複ゼロが絶対条件**）
3. USP・勝ち筋と接続しているか
4. 商圏として妥当か（地域語を含む場合）

《競合が起きた場合》
同一の語を複数ページが欲しがる場合、次の順で決着させる。
- ページ意図の代表性が高い方を主役にする
- 敗れた方には、意図の違いを表す別の派生語を当てる
- 両ページに「書き分け宣言」を必ず作る（STEP 6）

《主役KWが見つからないページ》
派生語が尽きた場合、無理に当てず「主役KW未確定」として報告する。
（担当者判断で、意図語を仮置きするか、種KWの追加を行う）

### STEP 5｜サブKWの配置

各ページに、主役KWを補うサブKWを0〜4語配置する。

サブKWの種類：
- 【包含】主役の意図に含まれる下位需要（例：主役「内窓 費用」→ サブ「内窓 補助金 上限」）
- 【隣接】同じ段階で角度が違う需要（例：「費用」に対する「相場」）
- 【質問】そのページで答える質問形（FAQ・見出しで受ける）

各サブKWに、使用予定を指定する：`h2見出し` / `導入・本文` / `FAQ`
※この指定は工程13（h1）・工程14（見出し＋文章）への指示になる。

《容量の目安》1ページ＝主役1＋サブ2〜4。5語を超える場合は詰め込み警告を出す。

### STEP 6｜書き分け宣言

似た需要を担当する近接ページのペアすべてに、書き分け宣言を作る。

形式：
「{ページA}は【◯◯したい人】に応え、{ページB}は【△△したい人】に応える」

例：
「/service/window/ は【内窓そのものを知りたい人】に応え、
  /solution/cold/ は【寒さという症状から解決策を探している人】に応える」

これは工程11〜14で、title・h1・本文が重複しないための拘束条件になる。

### STEP 7｜検査

□ 通常割当ページ全件に主役KWが1語ついているか（未確定は報告済みか）
□ 主役KWの重複がゼロか（**最重要**）
□ 対象外3ページにKWを割り当てていないか
□ 可変2ページに指名系以外のKWを割り当てていないか
□ 派生語がすべてコンテキストに実在する要素から展開されているか
□ 検索ボリューム等の数値を書いていないか
□ 近接ページのペアに書き分け宣言があるか
□ 1ページあたり5語超のページに詰め込み警告を出したか

## ■ 設計意図（運用者向けメモ）

| 設計要素 | 狙い |
| :-- | :-- |
| 1語＝1ページの絶対化 | カニバリは後工程では直せない。ここで潰す |
| 派生語をコンテキスト実在範囲に限定 | 対応していない地域・サービスのKWを作らない（誇大表示の予防） |
| 数値の創作を明示的に禁止 | 実査しない工程が、実査したかのような出力を出すのを防ぐ |
| 「判定していないこと」をPART Bに明記 | 下流が本工程の出力をSEO評価と誤解しないため |
| 書き分け宣言 | 工程11〜14が重複を作らないための拘束条件。ここでしか作れない |
| 主役KW未確定を許容 | 3語からの派生には限界がある。無理に埋めさせると質の低い語が混入する |
