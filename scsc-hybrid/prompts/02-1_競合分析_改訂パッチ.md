## ■ 改訂の理由

ハイブリッド工程では、**キーワード実査（allintitle等）を行わない**ことが確定している（設計判断 D2）。
その代わりに工程11（タイトルタグ）の埋没判定を担うのが、本工程の出力である。

```
工程11 【検査6】埋没判定 ＝ 競合3社のFVキャッチと同じ土俵になっていないか
工程11 【検査7】共通USP（2社以上が言っている表現）を使っていないか
        ↑ この2つの検査の材料は、本工程の出力しかない
```

つまり本工程は、いつの間にか**サイト全体の差別化を担保する唯一の実測工程**になった。
にもかかわらず、現行の出力は「FVキャッチを原文ママで1行」までしか持たない。
これでは工程11が「同じ土俵か」をAIの主観で判定することになり、検査が成立しない。

| 現行の出力 | 工程11が必要とする形 |
| :-- | :-- |
| FVキャッチ原文ママ（1文の文字列） | その文の**どの語が差別化を担っているか**の分解 |
| 共通USP（3つ程度の箇条書き） | title作成時に**使ってよい語／使ってはいけない語**の判定表 |
| CTA／導線（最優先の1つ） | 工程03が探す「**入口の隙**」＝入口CTAの有無 |

改訂は上記3点への対応と、限界の明示の計4件。**調査の追加作業は発生しない**
（同じページを見ている最中に、見え方を分解して書くだけである）。

```

```

## ■ 追記3｜STEP2 と STEP3 の間に「STEP 2-2」を新設

**挿入位置：** 「### STEP 2：「共通のUSP（＝消す対象）」を抽出する」の直後、STEP3の直前

```
### STEP 2-2：「使用回避語リスト」を作成する（工程11への引き渡し）

STEP1⑥で分解した3社分の訴求語・便益語を突き合わせ、
後工程（工程02-2のUSPキャッチ・工程11のタイトルタグ）が
**使ってよい語／使ってはいけない語**を判定できる表を作る。

判定は「語の字面」ではなく、**その語が顧客に約束している便益**で行う
（STEP2の「同義の判定原則」と同一基準を適用する）。

区分は3つ。

| 区分 | 定義 | 後工程での扱い |
|---|---|---|
| 【回避必須】 | 3社のうち**2社以上**が使用している訴求語・便益語（＝共通USPを語レベルに落としたもの） | title・USPキャッチに**使用禁止**。検索結果で区別がつかないため |
| 【要注意】 | **1社のみ**が使用している訴求語・便益語 | 使用可。ただし**約束する便益を変える**こと（同じ語でも別の約束なら可）。使う場合は理由を1行付す |
| 【空席】 | 3社の**いずれも使っていない**便益語のうち、顧客が求めていると考えられるもの | 優先的に使ってよい候補。**ただし本工程は自社の事実確認を行わない**ため、実際に言えるかどうかは工程02-2・工程04で確認する |

**記載ルール：**
- 各語に、その語が約束している便益を必ず併記する（例：「地域密着」→ 約束：近さ・すぐ来てくれる）
- 【回避必須】には該当競合（①②③）を付記する
- 【空席】は3件を上限とする。埋まらない場合は実在する数だけ記載し「◯件のみ」と明記する
- **語を創作しない**。【回避必須】【要注意】は原文に実在する語のみ。【空席】のみ、
  「3社が言っていない便益」という性質上、担当者の言葉で書いてよいが「（仮説）」を付す
```

## ■ 設計意図（運用者向けメモ）

| 設計要素 | 狙い |
| :-- | :-- |
| 語レベルの分解を必須化 | 「同じ土俵か」という主観判定を、語の照合という機械作業に落とす。実査を採らない以上、ここを曖昧にすると差別化の担保が消える |
| 迷う語は訴求語に寄せる | 判定に迷ったとき、回避側（安全側）に倒す規則を先に決めておく。逆にすると回避漏れが出る |
| 入口CTAの「なし」を明記させる | 空欄は「調べていない」と「存在しない」の区別がつかない。工程03が探す隙は、後者でしか成立しない |
| 【空席】に「自社が言えるかは未確認」と書かせる | 本工程は競合しか見ていない。自社の事実確認は工程02-2・S14の役割であり、ここで確定させると根拠なきUSPの入口になる |
| 「取得していないもの」を出力に固定 | 工程11のPART Bの限界表示と同じ文言が、上流にも残る。誰が読んでも実査していないことが分かる |
