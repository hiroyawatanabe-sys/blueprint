# 執筆の憲法

■ 証拠範囲の絶対（最重要）
事実の主張（数字・実績・資格・保証・対応範囲・年数・地域）は、
【A】内の S14 事実・数値台帳に実在するものに限ります。
**台帳に無い事実を1つでも書いてはなりません。**
- 使用時は台帳の No. を控え、PART 0 の事実照合表に併記する
- 台帳の「原文表記」を崩さない（例：「2,300件」を「約2300件」にしない）
- 公開可否が「要確認」の事実は使用しない
- 表現に迷う場合は「主張を弱める」方向で解決する（誇張方向の解決を禁止）
※【A】に S14 が含まれない場合は【A】全体を出所とみなすが、
  その場合も出所箇所（章・行）を事実照合表に記録すること。

■ メタ4点は「転記」である（本工程で作らない）
title（工程11確定）・description（工程12確定）・h1（工程13確定）・
keywords（工程08の主役KW＋サブKW・最大5件）は前工程の確定値です。
本工程はこれを**一字一句そのまま転記**します。
本文を書いた結果、メタを変えたくなった場合も変更せず、差戻し事項として起票してください。

■ 約束回収の原則（3点セットの回収）
このページの3点セットは役割分担が確定しています：
title＝約束／description＝中身と根拠／h1＝ページ内の宣言。
- 本文冒頭のリードは、h1（宣言）を受け、description の結論（answer_core）を
  詳述する形で書き始める（結論を先に、説明を後に）
- title の差別化要素（differentiator_used）は、MV〜最初のセクションで最初に登場させる
- description が約束した数字・内容は、本文で必ず回収・詳述する

■ KW規律（工程08の割当に従う）
- 主役KW：h1 に含まれている（工程13確定）。本文では自然な文脈で適度に使用する
  （密度の作為的操作・連呼を禁止）
- サブKW：工程08の usage 指定（h2見出し／導入・本文／FAQ）に従って消化する。
  各セクション見出しに自然に1回まで
- 語彙：一軍KWの反復ではなく、関連語・共起語で語彙の幅を作る
- 読者の言葉（悩み語・決め手語＝【A】のペルソナ情報）を、悩みの描写と決め手の提示に使用する
- 【A】に使用回避語リスト（S5-3）がある場合、
  **【回避必須】の語を見出し・キャッチ・CTA文言に使わない**（本文中でも多用しない）

■ 分量・書式の遵守
【B】執筆指示書の各項目の文字数は目標値です。**±10%以内**に収め、下限割れを禁止します。
「0文字」の項目は本文を書かず空欄にします。文字数指定のない項目は同種の項目に合わせて簡潔に書きます。
書式に入らない文章を書かないでください。
（【A】が別の許容幅を明示している場合はそちらを優先し、採用した基準を PART 0 に記す）

■ 構造の遵守（第1層の規律）
【B】は設置済みパーツから自動生成された「構造の正」です。
セクション番号・項目・順序を変更・追加・削除しないでください（C1 2階層モデル：第0層の侵犯）。
指示書にない項目を作らないでください。「（入力項目なし）」のセクションは出力しません。
【A】の設計と【B】の構造に齟齬を発見した場合（設計にあるセクションが指示書に無い等）は、
執筆で吸収せず、差戻し事項として起票してください（正すべきは設置パーツの側です）。

■ fieldset（繰り返し項目）の件数規律
「※件数は自由です」とある繰り返し項目の件数は、好きに決めてよいという意味ではありません。
**【A】の設計値から確定します**：
- 事業紹介系 → 事業数（S2の度数配分／工程06の詳細タブ数）
- USP系 → 確定USP数（S6：メイン1＋サポート）
- 悩み・課題系 → 工程05の充填指定にある悩み項目数
- CV系 → 確定CTA体系（S7）の枠数
設計値が【A】に見当たらない場合のみ内容から件数を決め、根拠を1行で記録します。

■ 共通パーツの規律
【A】で「共通」「全ページ再利用」「正本からコピー」と指定されたパーツ
（CVセクション・フッター・事業所案内等）は、正本の文言を**そのまま転記**します。
ページ側での言い換え・改良を禁止します
（共通パーツは単一ソース管理であり、1ページの改良が全ページの不一致を生みます）。

■ CTA文言・リンク先の規律
- ボタン文言は【A】の確定CTA文言体系（工程03確定）を使用します。
  **本工程で新しいCTA文言を発明しません**
  （最終文言の調整は工程15の役割であり、本工程の原稿は工程15への入力になります）
- リンク先は【A】の確定ページ台帳（工程06）に実在するディレクトリのみ。
  **推測でURLを作らないこと**
- リンク文言は先の便益を示す具体文言にします（**「こちら」を禁止**）

■ 水増し禁止
同義反復・言い換えの繰り返し・「いかがでしたか」型の空文・一般論の長い引き写し・
冗長な敬語・KWの不自然な反復で字数を稼がないでください。
増量は、【A】に実在する情報（事例・数値・手順・地域文脈・判断基準・注意点）の
追加によってのみ行います。

■ トーンの統一
文体はターゲットの知識水準・年齢層（S3）に合わせ、【A】のトーン指定（S9）と整合させます。
ターゲットが嫌う表現・誇大表現・証拠なき最上級を避けてください。

■ 要確認・許諾未確定の扱い
【A】が「要確認」「許諾未確定」「保留」「公開ブロッカー」と印を付けた事実・素材は、
確定した事実として書きません。【A】が指定する保留処理（仮置き・非表示・代替表現）に従い、
該当箇所を PART 0 の差戻し事項に列挙します。

■ Answer First（AIO実装）
各項目は「結論先行→根拠→詳細」の構造で書きます。
引用可能な事実（主語明確・数字入り・1文完結）を含めてください。

# このページの座標

【A】に記載された当該ページの「役割・意図・主対象Stage・主役CTA」を座標の正とします。
そのうえで、ページ種別ごとの共通政策を適用します。

- **TOP**：全流入の受け皿と振り分け装置。各セクションはダイジェストであり、詳細は下層の役割
  （**最大化抑制**：トップの肥大は下層ページとのカニバリと読者の迷子を生む）。
  ファーストビューで「この会社が何屋で、何が違うのか」を提示し、
  心理段階の並び（【A】の訴求POINT）に沿って
  「自分ごと化」→「解決できそう」→「この会社なら任せられる」→「行動」と温度を上げ、
  最大CTAへの動線をページ全体で一貫した確定文言で示す
- **一覧ページ**：各詳細への正しい振り分けが仕事。詳細の中身を語り尽くさない
- **詳細ページ（事業・USP・課題解決）**：1テーマを深掘りする。
  近接ページとの**書き分け宣言（工程08）**を守り、隣のページの主題を侵食しない
- **CVページ**：情報の追加より摩擦の除去。不安除去の確定文言と行動の明確化に徹する
- **デフォルト定型ページ**：定型文のみ。創作しない

# 実行タスク

## STEP 0｜入力検証（執筆前の門番）
- 【A】【B】が揃っているか。メタ4点の確定値（title／description／h1／keywords）が【A】に含まれるか
- 【B】のセクション構成と【A】のページ設計を突き合わせ、対応付けられないセクションが無いか
- 不足・齟齬があれば**執筆せず**、不足項目を明示して停止する

## STEP 1｜執筆前チェックイン
執筆を開始する前に、以下を整理・宣言してください。**チェックインなしの執筆開始を禁止します。**
- a. 約束回収リスト：title・description・h1 が記載する要素を列挙し、
  どのセクションで回収するかを対応付ける
- b. 事実リスト：このページで使用可能な事実を S14 台帳から **No. 付きで**全列挙する。
  **このリストに無い事実は本文に書けない**ことを宣言する
- c. 語彙割当表：主役KW・サブKW（usage指定付き）・関連語・悩み語・決め手語の使用計画
- d. fieldset件数表：繰り返し項目ごとに「件数・設計値の出所」を確定する
- e. 文体宣言：このページの文体と、避けるべき表現（S5-3【回避必須】語を含む）の確認

## STEP 2｜見出しの確定
- h1：**工程13の確定値を転記**する（変更禁止。不都合があれば差戻し事項へ）
- 各セクションの見出し：内容が具体的に分かるものにする（「〜について」型の曖昧見出しを禁止）。
  サブKW（usage=h2見出し）はここで消化する
- 見出しだけを通読して「ページの主張の流れ」が伝わるかを確認する（伝わらない場合は再設計）

## STEP 3｜セクション順に執筆
【B】のセクション順に、指定された項目を埋めていきます。
入れ子セクション（`1-1` のようにハイフンが付くもの）は親セクションの枠の中に入るパーツです。
親＝枠の見出し、子＝中身として、内容が重複しないようにしてください。
心理段階（【A】の訴求POINT）の温度がセクションを追うごとに上がるよう、接続と引きを設計します。

画像のALTは「こういう画像を用意する」という後工程への指示を兼ねます。
その画像に何が写っているかを60字以内目安で書き、**KWの詰め込みを禁止**します。
人物が写る想定の画像は、【A】で実在人物の素材提供が確認できる場合
（代表者・スタッフ・掲載許諾済みの施主等）を除き避けてください。

## STEP 4｜全数検査
執筆後、以下を実行し、結果を PART 0 に併記してください。不合格項目は修正して再検査します。
1. **分量**：項目別文字数（目標±10%内か・下限割れなしか・0文字項目に書いていないか）
2. **KW**：主役KWの自然な使用（連呼なし）／サブKWの usage 指定の消化状況
3. **約束回収**：回収リストの全項目が本文で回収されたか
4. **事実照合**：全ての数字・主張に S14 の No. があるか（**出所なき記述の検出＝即修正**）
5. **導線**：CTAの位置と文言（確定文言体系と一致か）／リンク先が確定ページ台帳に実在するか／
   「こちら」リンクの不使用
6. **Answer First**：各項目が結論先行になっているか
7. **水増し**：同義反復・空文・一般論の引き写しの検出＝削除し、不足分は事実の詳述で埋め直す
8. **トーン**：文体の一貫性／誇大表現・NG表現・回避必須語（見出し・CTA）の不使用
9. **読みやすさ**：見出しスキャンで流れが分かる／モバイル想定の段落長
10. **メタ転記**：title・description・h1・keywords が前工程確定値と一字一句一致しているか
11. **構造・件数**：【B】のセクション・項目と過不足なく一致しているか／
    fieldset件数が STEP 1-d の確定値どおりか

## ■ 設計意図（運用者向けメモ・原案からの変更点）

| 変更 | 理由 |
| :-- | :-- |
| メタ4点を「作成」から「転記」に変更（最重要） | 原案はSTEP 2でh1を作らせていたが、h1は工程13・titleは工程11・descriptionは工程12で確定済み。ここで作り直すと二重確定になり、3点対照表（約束／根拠／宣言）と検査済みの文字数・KW条件が壊れる。字数基準の二重管理（例：description 80〜100字 vs 案件文書の別基準）も転記化で消える |
| 事実の出所を「コンテキスト全体」→ S14台帳＋No.引用に特定 | 「実在するものに限る」は判定先が無ければ検査できない。C1・工程11〜13と同じ規律に統一し、検査4を照合作業にする |
| fieldset件数「自由」→ 設計値優先 | 件数はコンテンツの意図で決まる（USP数・事業数・悩み数）。上流で確定済みの値をAIに再判定させない |
| 共通パーツの転記規律を新設 | CV3点セット等は「正本からコピペ」の単一ソース運用。ページ側の善意の改良が全ページ不一致を生む |
| CTA文言の発明禁止＋工程15への役割分離 | D10（工程15に本文抜粋を渡す）と整合。14で文言を確定させると15と二重確定になる |
| 「トップページの座標」→ ページ種別ライブラリ化 | 1ページ＝1実行の汎用Promptにするため。当該ページの座標自体は【A】が正 |
| STEP 0（入力検証）を新設 | 【B】は機械生成ゆえ、設置ミスもそのまま写る。執筆で吸収させず、設置パーツ側へ差し戻す経路を作る |
| 検査10（メタ転記一致）・検査11（構造・件数）を追加 | 転記とfieldset規律は、検査が無ければ努力目標で終わる |
| 人物写真の除外に例外を追加 | 代表挨拶ウィジェット等、実在人物の写真が正しい箇所が存在する。一律禁止だと指示書と矛盾する |
| ±10%を既定とし【A】の別基準を許容 | 原案内で±10%と±20%が併存していた。既定を1つに固定し、案件別の上書きは記録付きで許す |
