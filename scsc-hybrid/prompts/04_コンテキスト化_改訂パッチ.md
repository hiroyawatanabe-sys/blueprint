## ■ 改訂の理由

統合版コンテキストは、工程05〜13の**すべてが読む唯一の情報源**である。
ハイブリッド化で下流工程が変わったため、現行フォーマットに3種類のズレが生じている。

### ズレ① 下流が要求する項目が、統合版に存在しない

| 下流工程の要求 | 現行の統合版 |
| :-- | :-- |
| 工程08「種KWを構成要素に分解して派生させる」 | S4は上位検索KW①〜③を**羅列するだけ** |
| 工程11 検査7「共通USP（2社以上）を使うな」 | S5-2に共通USPはあるが、**語レベルの判定表が無い** |
| 工程06「CTAの着地ページを必ず用意する」 | S7にCTAはあるが、**着地先ページ要求が無い** |
| 工程11・12・13「数字・実績は統合版に実在するものだけ」 | **数字が S1／S2／S6／S10 に散在**し、一覧が無い |

### ズレ② S8 が旧工程の前提のまま残っている

現行 S8 は、`{{ページツリー全文}}` を
「①ヒアリング結果 > 12. 参考サイト要点の明文化」から転記する設計になっている。

これは**旧「コンテンツ洗い出し → 35ページ分類」工程の前提**である。
ハイブリッド工程では **型A（型A'）が正**であり（設計判断 D11）、
ページ構成は工程06が型Aからの差分として確定する。

このまま残すと、統合版コンテキストに「参考サイト由来のページツリー」が載り、
工程05・06がそれを構成の根拠と誤読する。**齟齬の再生産経路になる。**

### ズレ③ 統合版が「事実の唯一の出典」として機能していない

工程11・12・13 は揃って「統合版コンテキストに実在する数字だけを使え」と規定している。
しかし現行の統合版は、数字が散在し、**公開可否・出典が構造化されていない**。
結果、下流のAIが「どこかに書いてあった数字」を拾って誇大表示になるリスクが残る。

改訂は7件。**S0〜S13の既存構造は保ったまま、行の追加と S8 の役割変更、S14・S15 の新設を行う。**

## ■ 設計意図（運用者向けメモ）

| 設計要素 | 狙い |
| :-- | :-- |
| S14 事実・数値台帳の新設 | 工程11・12・13が揃って「実在する数字だけ使え」と言うのに、その出典が定義されていなかった。台帳が無ければ検査は成立しない。誇大表示の予防装置でもある |
| 「埋めるために創作するな・空でよい」の明記 | 台帳を作ると「埋めなければ」という圧力が生まれる。空を許容すると先に書いておく |

| S8 の役割変更（唯一の削除） | 参考サイトのページツリーが統合版に載っていること自体が、旧工程の残骸。型Aが正である以上、ここを断たないと齟齬が再生産される |
| S4-2 の商圏上限 | 工程08は「対応していない地域を派生させない」と規定されているが、その範囲がどこにも定義されていなかった |

| 転記の再編集禁止 | 工程04は「統合」の工程であり、判断の工程ではない。要約すると工程02-1・03の粒度設計が無意味になる |
