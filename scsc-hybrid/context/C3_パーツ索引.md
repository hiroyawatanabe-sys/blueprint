# C3｜パーツ索引（機能別）

> **目的**：型Aシートの列（利用可能パーツ2〜4）で対応できない**列外逸脱**が起きたとき、
> 「どのパーツで受けるか」を**担当者の記憶や勘に依存させない**ための共通資産。
> 逸脱起票（C1-3）の「受けパーツ候補」欄は、必ず本索引を照合して記入する。
>
> **本書の位置づけ：たたき台（v0.1）**
> 現時点で判明しているパーツのみを収録している。収容仕様（テキスト上限・画像点数・n設計可否）は
> 大半が未確認であり、`要確認` と明記した。実機確認・開発元照会で順次埋める。
> **未確認のパーツに「適合」判定を出してはならない**（C1-5）。

---

## 使い方

1. 逸脱が発生したら、まず**機能分類**（下表の見出し）で当たりをつける
2. 候補パーツの**収容仕様**を確認する。`要確認` の場合は、類似パーツの実績値の80%を暫定上限として扱い、`要再確認` フラグを立てる
3. 該当が無ければ **「索引に該当なし＝新設アラート」** として起票する。近いパーツと差分を書き添える
4. 採用したパーツは、本索引の「使用実績」に追記する（索引を育てる）

## 9. 収容仕様の既知情報（パーツデフォルト値・統合版より）

REVOLUTIONパーツデフォルト値の突合結果から、**42のユニークUUID・105項目**が判明している（確定99／要確認6）。
UUIDとパーツIDの対応表が未整備のため、本索引とは現時点で紐づいていない。**第0層で対応表の整備が必要**。

### 代表的な設定文字数

| 入力項目 | 設定文字数 |
| :-- | :-- |
| `fieldset:title` | 20（最頻値） |
| `fieldset:text` | 40〜300（ブロックにより異なる） |
| `sec_title` / `sec_subtitle` | 20 |
| `table:td` | 30 |
| `contents` | 150 / 350 |

### 担当者間で値が不一致のまま未採決（6項目）

| UUID | 入力項目 | 候補値 |
| :-- | :-- | :-- |
| `d9250fcf-…` | text | 600 / 700 |
| `677ac4a8-…` | fieldset:text | 300 / 250 |
| `45c497b3-…` | fieldset:fieldset:th | 20 / 15 |
| `45c497b3-…` | fieldset:fieldset:td | 70 / 80 / 100 |
| `240f1efc-…` | fieldset:th | 20 / 10 |
| `240f1efc-…` | fieldset:td | 10 / 20 / 23 |

> これらを使うブロックでは、**最も小さい候補値を暫定上限**とし、`要再確認` を立てる（安全側に倒す）。
> また `7b6926af-…` の `fieldset:text` が **0文字指定**になっており、意図的か入力漏れか未確認。
