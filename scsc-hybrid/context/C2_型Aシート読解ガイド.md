# C2｜型A／型A' シート読解ガイド

> 一括生成シート（型A・エコマド工房仕様＝型A'）の構造を定義する。
> 工程05〜07はこのシートを母集団として読むため、**列の意味を正しく解釈できることが前提**になる。
> 本書は実ファイル（型A.xlsx／エコマド工房紹介案件.xlsx）を読み取って作成した。

---

## 1. ファイル全体の構造

- **1ページ＝1シートタブ**。タブ名がページを表す（例：`TOP` `会社情報` `事業紹介詳細1` `USP詳細1` `課題解決詳細1` `FAQ` `サイトマップ`）。
- 列は最大66列（A〜BN）まで使う。**縦がブロックの並び順＝ページ内のセクション順**である。
- 型A（汎用）は42タブ、型A'（エコマド工房仕様）は33タブ。**同一スキーマの別インスタンス**であり、読み方は共通。

### 型A と 型A' の主な違い（第0層で決定済み・第1層で変更しない）

| 項目 | 型A（汎用） | 型A'（エコマド工房仕様） |
| :-- | :-- | :-- |
| 実績系タブ | お客様の声一覧／お客様の声詳細1 | **施工事例一覧／施工事例詳細**（代用コンテンツ「名伏せ事例」を採用） |
| 事業詳細タブ | 事業紹介詳細1〜4 | 事業紹介詳細1（1本） |
| USP詳細タブ | USP詳細1〜3 | USP詳細1（1本） |
| 課題解決詳細 | 課題解決詳細1〜3 | 課題解決詳細1（1本） |
| CVページ | CV独立4ページ（一般問合せ／事業問合せ／事業見積／エントリー） | **`/contact/` 1枚**（フォーム＋電話＋LINE＋流れの説明を同居） |
| TOPブロック数 | 標準構成 | 窓断熱向けに調整済み |

> **既知の不具合（第0層で是正すべき）**：型A'の「施工事例一覧」タブのディレクトリが `/voice/detail1/`（＝詳細）、「施工事例詳細」タブが `/voice/`（＝一覧）と**入れ替わっている**。また `$article_code` が `projects` / `voice` / `case` で揺れている。**正は `/case/`**（C1参照）。第1層で転記する際は現物を必ず確認すること。

## 2. シート冒頭（ページ属性行）

各タブの先頭数行が、そのページ自体の属性を持つ。

| 行 | 列 | 内容 |
| :-- | :-- | :-- |
| R1 | A〜F | ヘッダー行：`ページ種別` `アーティクルコード` `ディレクトリ` `ページ名` `ページごとの指示` `キーワード` |
| R2 | A / C / D | 値：`normal` / `/`（ディレクトリ）/ `HOME`（ページ名） |
| R3 | A / C | `共通見出し` / 使用する見出しパーツID（例：`id:172819,　id:172819,　id:172819`） |
| R4 | A / C | `共通ボタン` / 共通ボタンのパーツID（例：`id:280661`） |
| R5 | A / B / AY〜BD | ブロック表のヘッダー行：`テキスト量` `コンテンツ訴求POINT` … `利用可能パーツ２〜４` `代用できるコンテンツ１〜３` |

> **R1のF列「キーワード」**：ページ単位のキーワード欄が既にシートに存在する。工程08（KW割当）の出力はここに着地させられる。

## 3. ブロック行の読み方（本ガイドの中核）

R6以降が**ブロック（ページ内セクション）の並び**である。1ブロックは複数行にまたがり、**A列またはB列に値がある行がブロックの開始行**にあたる。

| 列 | 意味 | 例 |
| :-- | :-- | :-- |
| **A** | **テキスト量**（このブロックの想定文字数） | `160` `300` `20` `0` |
| **B** | **コンテンツ訴求POINT**（戦略的役割＋**心理段階**） | `【見るレベル／ブランディングコンテンツ】` |
| D〜AV | ブロック内の**要素・見出し・本文の実データ**（列位置は要素ごとに異なる） | `事業紹介一覧` `Our Business` `LINKボタン` `/service/` |
| **AW** | **パーツIDとフィールドマッピング** | `id:223874` `$sec_title` `$button[href]` `=P41` |
| AX | パーツの**役割説明**（そのブロックが何のために存在するかの解説文） | `メインビジュアルは閲覧者が最初に見る箇所であり…` |
| **AY〜BA** | **利用可能パーツ２〜４**（＝このブロックで**交換してよい代替パーツID**） | `260220` `176217` `223874` |
| **BB〜BD** | **代用できるコンテンツ１〜３**（＝このブロックで**差し替えてよい代替コンテンツ**） | `プラン・メニュー紹介一覧` `サービス一覧` `店舗・サービス拠点一覧` |

### 決定的に重要な点

**AY〜BD列が「第1層で許される自由」の定義そのものである。**

- 差し替えたいコンテンツが **BB〜BD列にあれば → 列内（許容・記録のみ）**
- 使いたいパーツが **AY〜BA列にあれば → 列内（許容・記録のみ）**
- どちらにも無ければ → **列外逸脱（C1の起票フォーマットで起票）**

過去案件で「お客様の声 → 名伏せ事例」の差し替えが行われたが、これは型A'の代用コンテンツ列に載っている選択肢であり、**齟齬ではなく正常動作**だった。ただし列を参照した記録が残っていなかったため、事後に検証できなかった。列から明示的に選び、記録することが工程05の要件である。

## 4. 心理段階（B列）の並び ── 導線が焼き込まれている

B列の `【 】` 内が**3D-CMFの心理段階**を表す。ブロックはこの順に並んでおり、**型Aの時点で導線が設計済み**であることを意味する。

```
【見るレベル】
  ↓
【見るレベル／ブランディングコンテンツ】
  ↓
【興味喚起／USPコンテンツ】
  ↓
【ユーザ1stコンテンツ】
  ↓
【決意フェーズへ】
  ↓
【比較検討対策】
  ↓
【背中押し】
  ↓
【背中押し⇒仕様確定へ】
  ↓
【安心コンテンツ】
  ↓
【コンバージョン】
  ↓
【専門性、とは系、経験性】（＋SEO対策コンテンツ）
  ↓
【デフォルト】
```

工程07（導線差分設計）は、この並びと各ブロックの `$button[href]` を**正**として読み出し、CTA設計（工程03）の結果を重ねて**差分だけ**を指定する。ゼロから導線を描かない。

## 5. フィールドマッピング記法（AW列）

AW列の `$` から始まる値は、**REVOLUTION／OWLet の入力フィールド名**である。入稿JSONのキーと対応する。

| 記法 | 意味 |
| :-- | :-- |
| `$sec_title` / `$sec_subtitle` | セクション見出し／サブ見出し |
| `$button[href]` / `$button[link_text]` | ボタンのリンク先／ボタン文言 |
| `$fieldset[n][...]` | 繰り返し要素のn番目（n設計＝件数可変パーツ） |
| `$article_code` | アーティクル（記事機能）のコード。**ディレクトリと一致させる** |
| `$tag_name` | アーティクルのタグ名 |
| `$href_text` | リンクテキスト |
| `=P41` `=U64` 等 | **同一シート内の他セルへの参照**。表示値をそこから引く |
| `h:345635` | ヘッダーパーツの指定 |
| `id:302754` / `id:-371093` | パーツID（負値は別系統の識別子。現物確認が必要） |

> `=P41` のようなセル参照が入っている箇所は、**参照先セルに値を入れると自動で反映される**。工程05の出力は、参照先セルの位置を指定できると転記が速い。

## 6. ページ末尾の集計行

各タブの末尾に文字数の集計がある。

| 行の意味 | 内容 |
| :-- | :-- |
| `総量` | `=SUM(A4:A88)` 形式。ページ全体の想定文字数 |
| `BODY` | `=SUM(A19)` 形式。ヘッダー・フッター等を除く本文領域の文字数 |

工程14（見出し＋文章作成）の文字数チェックは、この値を基準に行う。工程05でブロックを差し替えた場合、**テキスト量（A列）の増減が総量に波及する**ため、差し替え時はA列の値も指定する。

## 7. 工程05〜07がシートから読むべき項目（チェックリスト）

作業開始時に、以下がすべて読めていることを確認する。

- [ ] 全タブ名の一覧（＝ページ一覧）
- [ ] 各タブのR2：ディレクトリ・ページ名・ページ種別
- [ ] 各タブのブロック行：A列テキスト量／B列訴求POINT（心理段階）
- [ ] 各ブロックのAW列：パーツIDとフィールドマッピング
- [ ] 各ブロックのAY〜BA列：利用可能パーツ2〜4
- [ ] 各ブロックのBB〜BD列：代用できるコンテンツ1〜3
- [ ] 各ブロックの `$button[href]`：導線のリンク先
- [ ] 末尾の総量／BODY集計
- [ ] `$article_code` とディレクトリの一致状況（不一致は起票）
